# 电商修图流

迁移状态：底层必须为 ygl-trees CLI 的高级封装。0.2.0 的独立账本需要迁移；先按根 SKILL.md 的最新迁移说明判断实际能力，旧流程仅供历史理解与隔离复核，不能据此在真实工作区扩展独立引擎。

从本文件向上三层定位项目根，读取 [SKILL.md](../../../SKILL.md) 作为业务操作入口。格式细节按需读取其中链接的 CLI 与宿主协议，不把历史设计接口当成已实现命令。

用户提供原图与目标，Agent 通过 `node src/cli.ts` 管理任务和版本，已有宿主负责实际图像工具调用。业务工作区显式指定；需求有文字且未停用就参与，后一步承接前一步通过检查的实际结果。

每次接手先读 project brief，任务显式绑定项目与目标版本，文档、候选和外部执行登记在统一索引。跨工作区用 context export/inspect/import 交换完整 ZIP，先只读预检再恢复；重复导入幂等，未知请求和历史权限不能因迁移而重新执行。

宿主工具可用并有实际授权时，记录 dispatch 后仅在首次非重放响应中调用一次；unknown 状态先对账，不能盲目再次出图。回接真实文件后检查合成候选，最终接受来自用户。独立 API fallback 尚未实现，offline 仅供 demo。

本目录是项目内的标准技能入口，详细流程只在根 SKILL.md 维护；依赖当前仓库的 CLI 与文档，不单独作为全局安装包。
