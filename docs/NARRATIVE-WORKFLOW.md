# 购买决策叙事与返图观察（Issue #11）

这是可复用流程说明，不是某个商品的正式业务design，不据此修改现有素材或接受。正式方案由既有原生design/spec/citation承载，软件校验身份、版本和已声明判断，不凭文本自动理解图像。

## 双轨与接手

业务设计轨：简报 → 参考/事实 → 买家决策矩阵 → 整套低成本分镜 → 风险代表样张 → 返图语义 → 全套审阅。

执行证据轨：goal/spec/design → 来源/冲突/保持项 → plan/真实授权 → 单次执行/原始回执 → media/派生父链 → hash绑定检查 → snapshot/preview → 用户明确接受/正式交付。任何一轨通过不代替另一轨。

接手从project brief.documents定位当前设计，artifact show读取正文。业务design至少包含本商品/使用者/市场、当前目标/任务/intent与来源身份、矩阵/分镜、事实及未知边界、风险代表、当前阶段/下一步。既有系列用artifact revise追加原生版本，不创建同义v2.md或新账本。

## 增量迭代与主动纠偏（Issue #17）

这是现有流程的执行改进，不新增计时服务、调度、业务账本或视觉评分DSL。完整需求见[Issue #17](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/17)，物理与厚度判据见[相对截面分项复核](PHYSICAL-REFERENCE-WORKFLOW.md#相对截面一致性与绝对毫米分项复核)。

1. **只读当前决定需要的变化。** 初次接手按brief定位；同任务后续单项调整先确认当前task/run revision、在途状态及确切文档身份，再回读变化的需求、facts/design版本和受影响消费者。可复用已经读过且身份/新鲜度条件未变的规则和来源；不能缓存猜动态revision、沿用已stale来源或省略冲突保护。完整JSON不可读/被截断则停止依赖其结论，不把片段当状态全貌。仅需几项状态时从受支持响应中摘取相关字段，控制工具输出，不反复输出整份大brief或另设影子缓存。
2. **合并准备，不改旧意图。** 同一在途批次收到新要求，先在现有来源/任务中保留并合并为下一计划的差异；旧请求真实prompt/参考和回执不改。先对账unknown、恢复received，不换键再派发。语义未变不机械修订goal/design/requirements，不每次复制同义payload、长期脚本或包装器；确需多对象更新时沿各公共接口/版本门禁做，不声称跨调用天然原子。
3. **返图即检查，不等提醒。** 在任何总体判断、接受或交付之前查看确切hash的实际候选，按本次风险检查数量/构成、可比较部件的截面一致性、书籍的承托/靠墙与前后后仰、关键内容义务及图文。绝对毫米可UNKNOWN但可见相对矛盾仍须FAIL；正常透视差异不能误判。未看NOT_RUN，失败审阅候选不得包装成合格交付，技术文件PASS不代替图像判断。
4. **有动作就执行或明确停因。** 结构问题按[控制前检与三层对照](PHYSICAL-REFERENCE-WORKFLOW.md#结构纠偏的控制前检与三层对照)分别观察目标参考、原生返图和最终合成；原生未改对回参考/方法，原生已对但合成丢失才按证据修本地擦除/掩膜/阴影，不重复收费生成。变化量和区外保全不能证明结构成功，专项完成不冲掉旧FAIL。 说明具体观察、反例和返回阶段；当前授权/预算内可独立完成的分析、可验证本地修补/排版立即做，保留父链并复看新hash，不把同一动作写成“建议下一步”再等用户点名。结构失败先改变参考/制作方法，不反复堆prompt或默认整图重绘。缺事实/偏好/外发费用次数许可只集中问真正未决点，不重问已有裁定；没有实际工具就如实停对应动作，不能写“已修正”。
5. **计量沿用真实轨迹。** 利用已有tool/run timeline及测试/回执时间，分别记录读取/准备、外部等待、返图观察、本地处理/导出阶段及调用次数。缺阶段边界/时间则UNKNOWN或NOT_RUN，不倒填纯推理耗时。用户可见时间采样间隔与execute-api子进程耗时不是同口径，不混为一笔；无同约束前后原始轨迹，不报节省百分比。长时间无新证据或同因失败重复时，缩小下一动作/复用既有入口或报告具体限制；不硬编码通用秒数、不为RSI造新报告平台。

实际授权仍约束每一次新模型请求和质量修正：直接批量许可不是无限重试，达到费用/次数上限即停；unknown先对账，received本地恢复不重发。未接受候选不自动正式交付，必要检查不因效率目标删除或改成PASS。此流程的文字存在、载入或定时提醒不证明Agent已在真实返图中主动执行；行为、质量、时间和成本须依真实轨迹分别复验。

## 先矩阵，再制作

| 列 | 必填内容 |
| --- | --- |
| 稳定页/段ID与职责 | 买家当前疑问，不是白底/场景等固定位置 |
| 结论/承诺 | 看完应理解什么；概念表达与可验证事实分开 |
| 证据及限制 | 原生来源ID/version/hash与精确摘录、适用SKU/场景/时间、未知/禁止暗示 |
| 画面/文案/低成本分镜 | 主体、动作对象、构图、文案层级；文字分镜不能冒称已画线框 |
| 转场/购买增量 | 前后页怎样推进；删除本页会失去什么理由 |
| 验收与适用反例 | 对应哪项intent/coverage/invariant，以及何时应拒绝/保留UNKNOWN |
| 阶段/下一步 | 待证据/待分镜/代表样张/制作/排版/审阅；失败返回何处 |

先拆参考的说服职责和阅读顺序，再对本SKU逐条核证，不能复制参考卖点或把AI重建当实物依据。页数按职责和信息密度决定，不固定七图，不用连续人物动作替代购买理由的推进。

整套先以文字/线框低成本看顺序、节奏和冗余；代表样张选当前最高风险，如商品使用关系、白色部件质感、结构或信息密度，不只选漂亮首图。复用sample-first；已有明确直接批量决定保留其原文与范围并用direct-batch，不追加逐图审批，不伪造样张已过。

## 返图：先观察、再反例、后结论

实际查看最终候选文件后，用当前media id/hash在已有coverage/invariant/visual review观察字段记录：

1. **主体与对象**：谁在做什么，动作具体指向什么，在画面哪里？无人物或无动作时按本页职责说明不适用，不强填人物。
2. **商品关系**：商品怎样与动作、视线、结果或购买意义关联？“图里出现商品”不等于本页义务已被承接。
3. **物理与图文**：比例、结构、接口、构成、尺寸文字、包装暗示是否一致？哪些来自本SKU可靠证据，哪些仍未知？不能因图中能接触就判已适配，也不能用AI图证明规格。涉及尺寸/遮挡时按[物理参考方法](PHYSICAL-REFERENCE-WORKFLOW.md)核构型、基准、视角与可见端点；参数可靠但成像条件不足为UNKNOWN，不直接判几何FAIL。
4. **职责反例**：对使用/情感等适用页追问拿走/换掉商品后是否仍为同一张泛情绪图；对相邻页说明新增理由。白底/尺寸页按认知/规格判据，不机械套触摸反例。
5. **结论与下一步**：指出承接/未承接的具体义务和可见证据，记录复核者、方法、来源和适用范围。明显矛盾FAIL；缺证据或看不清UNKNOWN；未看记验证状态NOT_RUN，不提交虚构观察（既有覆盖聚合为NOT_EVALUATED）。必检缺口不能被总体PASS绕过。

观察可以结构化地写进现有文本字段，但不是新的JSON评分DSL。适用范围或来源缺失时保留未知，不由Agent补造授权。PASS只允许进入候选，不产生用户接受、商品事实确认、平台批准或整套交付。

## 同构正反例

| 场景与页职责 | 观察/依据 | 允许的判断 |
| --- | --- | --- |
| 礼赠意义；泛礼盒+旁置支架 | 手眼集中另一礼盒，支架无可见关系，缺本SKU包装依据 | 对“赠送该商品”义务FAIL/缺据UNKNOWN；不得元素齐全就PASS，也不得仅凭盒小断言装不下 |
| 介绍实际商品 | 人物介绍/观察同一完整商品；去掉商品会失去介绍对象 | 商品指代成立，可进入候选；不等于性能确认或用户接受 |
| 有本SKU真实包装资料的礼赠 | 精确来源与包装、视线/动作指代一致，商品可间接呈现 | 不因有礼盒或未触摸商品自动失败 |
| 无人物的白底认知/尺寸页 | 商品完整，尺寸字段有可靠来源，单位/对象一致 | 按职责评估，不新增必须有人/触摸门槛 |
| 美观人物场景但物理/图文冲突 | 插口关系或比例与来源/标注矛盾 | 具体义务FAIL，不能靠脚注挽救相反画面 |
| 遮挡、低清或尚未看图 | 核心对象不可辨或没有实际观察 | UNKNOWN或NOT_RUN；不从prompt推导PASS |

这些是方法示例/隔离夹具输入，不是自动视觉分类器。实际宿主看图、独立盲复核、用户接受分别报告，不能把已知反馈的回放当独立验证。

## 失败回到正确阶段

- 买家问题、缺理由、泛情绪：回矩阵/分镜，不无限加图。
- 事实、构成、包装未知：补必要证据或删无依据承诺，不从新图补造事实。
- 动作对象、接口、物理关系错：定向制作/有界修补，复看最终像素；已授权范围内不重复审批。
- 抠图/低清素材方法失效：回技术路线/代表样张，停止堆补丁。
- 脚注、字号、留白、语言：用原生asset transform本地排版，保全字体和输入，不重发正确模型图。
- 文件尺寸、顺序、ZIP上限：回导出编排，不出图补账，不覆盖旧交付。

最终审阅时再看实际PNG/JPEG和全套跳读/顺读，确认无无效重复、构成/包装/图文矛盾。基础检查由Agent承担，用户裁方向与最终确切范围接受；技术PASS、内容PASS、用户接受、正式交付各自留证。
