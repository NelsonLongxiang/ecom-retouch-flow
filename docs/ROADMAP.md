# 实现路线图

2026-11-15 用户确认开始：原生封装与缺口 → 工作流／ZIP 迁移 → 动态上下文。高级封装边界和所有登记工作区的统计范围已确定，不重复请求路线确认。

| 阶段 | 0.3.0 实施内容 | 验收依据 |
| --- | --- | --- |
| 原生承载 | 严格 JSON client、ygl 用户插件、既有原生实体、事务／幂等、profile 版本、原生工作区登记 | 原生实体可独立查询；初始化前后表清单相同；正常入口无 ledger |
| 工作流迁移 | 原生目标／任务、需求组、顺序步骤、宿主派发／回接、检查接受交付、unknown、只读 legacy 映射 | 真实 CLI 与本地图像夹具；重放不重发、尺寸和关系可核验 |
| ZIP 迁移 | 原生 v2 项目图、可读 brief、素材、预检、事务恢复、幂等及 clone、历史权限隔离 | 源只读、恢复后身份／进度保留、冲突无覆盖、后续进度不回滚 |
| 动态上下文 | 标签更新、用户评分／结语／完结、原生 design/spec 检索引用、不同项目数频率、二次分类及共现反馈 | 登记范围、去重／分歧／权威、方法版本、样本分母、引用快照及过期诊断 |

0.4.0 继续完成显式图像 API fallback：原生执行配置、请求与回执、外发／费用确认、按授权限制请求次数、单次提交、未知对账、原始结果和本地恢复；不新增提供商业务数据库。实现边界和操作见 [API fallback](API-FALLBACK.md)。

当前源码与验证入口见 [实现说明](IMPLEMENTATION.md) 和 [验证](verification/README.md)。本轮不自动迁移真实用户项目、不部署到共享 home、不调用真实 AI 或独立收费 API。0.2.0 的 42 项历史测试单独保留，不证明新架构验收。

后续真实商品试点仍需实际图像能力及适用授权，验证真实两步连续修图、语义保持和用户验收。2026-11-15 已另经授权完成一次合成素材的原生API实调，验证通道和接手；本轮E01–E07不延续该调用授权，也不据此声明商品质量通过。批量模型请求、多提供商、PG、完整生产故障矩阵和后台提醒未因当前实现被宣称可用。

2026-11-15 的本地草案E01–E07进入实现：E03已有结果待复核与显式重新采纳、E07关闭同步节点证据；E01用途与内容覆盖、E02多来源冲突和最小补证；E04逐项保持；E05原生本地裁切/蒙版/修补/合成/文字/缩放；E06稳定槽位快照、部分接受、完整/增量图片包。当前契约和命令见 [工程流程](ENGINEERING-CONTRACTS.md)，专项与完整验收分别报告，语义观察由实际宿主/人工提供，不默认接付费评估模型。

动态上下文当前为确定性检索与分析，加宿主 Agent 的专业解释；不另接付费模型或维护独立偏好引擎。时间窗口、提醒延后和自动语义分类仍属于后续交互扩展，具体边界在 [动态上下文规范](DYNAMIC-CONTEXT.md) 标注。
