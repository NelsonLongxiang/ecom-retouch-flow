# 产品物理参数到生图：公共方法与可视参考契约（Issue #16）

首版方法候选，适用于商品图制作、已有图纠偏及跨项目接手。需求来源为[Issue #16](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/16)；复用既有[字段事实](ISSUE-ACCEPTANCE.md#字段事实与用途)、[原生流程契约](ENGINEERING-CONTRACTS.md)、[叙事方法](NARRATIVE-WORKFLOW.md)和[宿主协议](HOST-EXECUTOR.md)。它不是几何引擎、自动视觉裁判或新业务账本，不授予实际图像调用、外发、费用、安装或部署权限。

公开材料只含合成同构参数及脱敏现象；不附用户原图、成品、身份、凭据、私网地址、本机绝对路径或业务包。下文的45/25/5和控制值30仅用于解释已披露的问题，不是商品默认值、当前业务事实或通用校准系数。

## 六层定义：不能相互覆盖

| 层 | 权威记录及最小内容 | 不得推出 |
| --- | --- | --- |
| 物理事实 | 原生product-facts spec＋实际来源；SKU、部件/字段、原值/约数/范围、单位、确认性质、单件/整套范围；构型/档位、空载/受载、测量起止点/基准及来源精度按主张需要在来源/结构说明中精确引用 | 模型画出来、用户觉得好看、控制值被调过，都不能修改实物规格 |
| 结构解释 | 关联任务的design/spec；部件数量、连接、接触平面、尺寸对应轴、内外尺寸、道具与随货的区别；缺证据明确假设/unknown | 从高度推厚度，从可见轮廓补侧板/内部/孔位 |
| 成像条件 | 同一design中的视角、透视、安装高度、前后深度、遮挡、可见端点与适用条件 | 单图白带高度等于实体高或统一像素比 |
| 可视参考 | 原生media的真实hash/尺寸/父链；design中的来源性质、用途、允许影响和不得复制项 | 示意图、非成品编辑稿或风格图等于实拍/实测 |
| 生成控制 | 冻结plan的prompt、references、region/coordinate_system及实际支持的executor选项；实验补偿与适用范围单独记 | 控制字串、seed、像素尺寸或实验经验等于物理事实；工具未支持的选项已生效 |
| 复核与接受 | 对确切media/hash的分项观察、反例及PASS/FAIL/UNKNOWN；真实用户接受范围、文件交付各自记录 | 视觉可用＝毫米精确＝用户接受＝整套交付 |

这些是业务文档的阅读与检查契约，不是六张新表或新增JSON schema。首版不扩展facts字段校验器：测量基准、结构和参考职责先写入已有design/spec正文；不能添加自定义键后声称plan/dispatch已执行它。

## 七阶段闭环与失败返回

| 阶段 | 最小动作与进入条件 | 原生可复核产物 | 失败／未知返回 |
| --- | --- | --- | --- |
| 1 参数与来源 | 读取本SKU原文/图，分高、厚、深、数量/对象与单位；记录构型/档位、空载/受载、从哪里量到哪里、基准及约数/范围/精度，未知保持unknown；只补影响本画面的缺项 | 来源spec/citation的ID/version/content_hash和精确摘录；facts字段；当前缺口 | 有冲突先回读来源，必要时conflict record/resolve；不凭AI图补确认 |
| 2 结构与装配 | 把字段映射到真实部件、数量、安装/连接/接触面；标明哪些部分可见、哪些是假设；道具不改商品构成 | 结构说明＋有来源和视角范围的invariant | 不确定隐藏装配只停依赖它的主张；无依据的侧板/厚度回来源，不先制作 |
| 3 视角与遮挡 | 定主展示面、相机/俯仰、前后深度、可见端点；区分完整实体、完整投影、遮挡后的露出部分 | 成像假设、unknown、条件化示意和不适用反例 | 基准/深度未知不写“已实测”；换视角重新判断，不固定比例 |
| 4 可视参考 | 先找已有实际工具与图；必要时由部件/截面示意→目标视角可见关系→明确轮廓的编辑参考，避免只反复加尺寸文字 | 每张media的ID/hash/父链、职责/非成品标识、事实/示意字段、不能复制项 | 职责冲突回设计；旧错误轮廓、尺寸标线、接缝/台阶残留回参考制作 |
| 5 场景与冻结计划 | 明确商品职责与道具关系；回读当前facts/design/参考/保持项，再冻结输入、步骤、坐标、实际选项和适用授权 | plan ID/hash、精确文档版本、media/hash、参考顺序/用途、检查项与当前next action | 缺执行权限只停调用；版本变动复核受影响计划，不能静默改旧快照 |
| 6 执行与回接 | 仅首次非重放dispatch且allow_execute=true才执行一次；接回真实原始字节，后处理独立派生 | 原生请求/回执/执行ID、输入/原生输出/派生尺寸hash与父链 | unknown先对账；received本地恢复不重发；缺工具不自动付费fallback |
| 7 观察与修订 | 看实际最终像素，逐部件/物品写观察→反例→结论；接受与交付分开 | exact hash的visual/invariant/coverage记录、用户反馈原文及范围、修订版本和消费者 | 明显矛盾FAIL，证据不足UNKNOWN，未看NOT_RUN；回到导致错误的阶段，不无限出图 |

资料足以支持当前视觉任务且授权覆盖时直接推进，不反复逐图确认。无侧面照片不一刀切阻断普通制作：可选保守视角、visible-only、关闭未核内部或省略未核承诺。隐藏连接、承重/安全和精确尺寸证据不足时，仅停止依赖它们的主张；不得用“概念图”掩盖明确相反的结构。

## 参数、基准与条件公式

合成同构说明：后板实体高45mm、前板实体高25mm、各板实体厚5mm是三类量。每个值都要指到部件、方向、测量起止点及基准；不能把白带、顶面厚度和整板高当同一对象。基准未知可如实记录unknown，同时保留用户确认的参数原文；参数已确认不等于装配基准也已确认。

同SKU也可能有展开/折叠、伸缩档位、安装状态、空载/受载等合法尺寸差异。先在来源与design正文明确当前适用状态，用已有稳定field key区分确需同时保存的量（如展开空载踏面高、折叠外廓厚），不要把它们混成同一尺寸或自动当冲突。保留来源“约”“范围”及已知精度/公差；现有facts.value支持字符串，不把约380写成精确380，也不从照片补公差。主张毫米精度、安全或承载时，按主张补必要测量条件与证据，否则UNKNOWN；普通外观任务不因此强制补齐无关参数。这是原生正文/既有字段的使用约定，不新增schema或自动状态判断。

仅在**共同高度基准、同一竖直方向、无装配起点差、近水平/正投影近似、前板遮住后板下段**等假设成立时，可用“45−25≈20mm露出量”作结构解释。它不是照片里量得的毫米数；不额外加减5mm厚度来凑图，也不要求两条白带像素比固定为1.8或0.8。

- 俯视角变化、前后深度差、错台安装、不同高度基准、透视或遮挡对象变化时，原近似不能直接使用。
- 仅在对应完整实体端点可见、对象/测量轴一致且透视已校正时，才比较实体的对应投影；单图缺条件就UNKNOWN，不假装相机已标定。
- 控制试验曾用30代替45的字串得到更合意视觉，只能保留为**生成控制实验**。事实仍是有来源的45；不得把30写回facts或尺寸标注。若控制与真实规格的表达冲突，先说明实验性质并修正参考职责/轮廓控制，不能把矛盾prompt当已解决。
- 两次出图还改变输入、描述或参考时标为confounded，不拟合“统一乘2/3”。新SKU重新读取其自身来源，不继承旧SKU数值、经验补偿或接受。

## 相对截面一致性与绝对毫米分项复核

来自[Issue #16的厚度复核补充](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/16#issuecomment-6919744638)，与[Issue #17主动纠偏](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/17)共用阶段2/4/7。这里只规定Agent检查问题和原生记录分项，不让软件从文字或图片自动量毫米。

- 先按本SKU来源识别真实部件与测量对象：板厚、前挡板立面高度、托面因透视呈现的深度不是同一量。同系列不同长度若明确使用相同板材/截面，只有来源允许的长度等参数可变；不将案例中的架体数量或10mm设为通用默认。
- 实看确切media/hash，沿同一块板及可比较的同类部件/连接处，主动检查无依据的渐厚/渐薄、重复叠层、加厚封边、异构截面和数量变化。不等用户点名才查；已有长度等FAIL保留，另记截面问题，不把旧失败候选改说成曾获接受的交付。
- **相对一致性与绝对精度分开**：有可比较的可见证据确认截面矛盾时，相对项FAIL；缺尺度、端面或标定而不能证实准确毫米数时，绝对项UNKNOWN。两者可并存，不能以总体“尺寸未知”冲淡可见FAIL，也不能因相对一致就把绝对毫米补PASS。
- 可比较必须先核部件身份、构型/状态、朝向、深度、遮挡和端面。斜视、近大远小、不同轴或不同深度带来正常像素宽度差，不机械要求所有边同像素厚；比较依据不足为UNKNOWN，不为“主动纠偏”制造假FAIL。未实际看图为NOT_RUN，原生未提交检查的视图保持NOT_EVALUATED。
- 遮挡严重或结构反复漂移时，主动返回阶段2/4：复用能看清端部/截面的产品参考、空架或结构母版，先核截面再进入陈列/场景；不是每个任务都强制加一张空架或新生图。若现有素材和工具不足，停依赖该证据的主张，保留未知，不为补测擅自调用模型或加付费请求。

阶段2/5预先声明保持项适用scope与required。原目标要求精确毫米时，UNKNOWN仍阻断该目标，不能事后降为可选、删失败项或用visible-only替代本来承诺的验证；有真实授权修订目标/计划则保留旧规范与结论。观察用已有invariant/visual review字段，下面仅是**已观察后如何分项登记的示例**，不是已看某张真实图的结果：

~~~json
{
  "items": [
    {"id": "relative-section", "verdict": "FAIL", "observations": "<确切图中可比位置的无依据厚薄/叠层差异>", "evidence": "<部件/构型/视角/端面比较依据及可见范围>"},
    {"id": "absolute-thickness", "verdict": "UNKNOWN", "observations": "<缺少可支持准确毫米数的尺度或端面>", "evidence": "<已查看范围与缺失证据>"}
  ]
}
~~~

先由实际来源建立对应invariant，再用真实hash/contract_id/method/reviewer/source提交合法检查。此处不新增verdict或schema；明显相对矛盾进入既有FAIL门禁，绝对未知继续独立可见。授权内可用且可验证的本地修正立即执行并复看新派生；结构性失败先改参考/制作方法，不盲目整图重生成，不改真实板厚凑图。

## 可视参考契约：一图一职责

每张参考至少在关联design中写清：media ID/hash/原始尺寸、父图ID/hash与来源、类型、适用SKU/部位/视角、事实字段/示意字段、允许影响、禁止复制、冲突处理、当前版本和复核状态。没有真实父图的原创示意明确记无父图，不伪造实拍来源；导入/本地变换已有图则保存实际父链。

| 参考类型 | 可以指导 | 必须标识／不能带入成品 |
| --- | --- | --- |
| 实拍或尺寸正确母版 | 有依据的可见商品结构、材质、边界；明确只保留哪些部分 | 实拍不能证明被遮内部；旧错误轮廓若在本轮纠正范围内，不再同时要求保持 |
| 部件/截面简图 | 参数与轴/部件的映射、装配假设 | 标“结构示意/非实测”；标线、文字、夸张厚度和剖面不复制到场景 |
| 条件化可见关系 | 当前视角/遮挡假设下哪些部分露出 | 条件不满足就失效；不是新的物理尺寸证据 |
| 非成品编辑稿 | 经明确修订的目标轮廓、降低露出部分等局部意图 | 标“非成品、非实测”；保留新轮廓，模型修复接缝、台阶、边缘、光影，不还原旧错误形状；不能把草稿残留当成品 |
| 风格/环境图 | 色调、构图、光线、场景语言 | 不借用他SKU尺寸、侧板/孔位、配件或随货数量 |

同一参考不得同时承担“保持原后板形状”和“降低后板露出”的相反职责。可以保留原图作材质参考、编辑稿作轮廓参考，但要在设计、prompt及每个reference.purpose里明确分工。若无可执行的优先顺序或职责仍冲突，回阶段4/5，不发送一个自相矛盾的参考包。

参数不服从时的最小路径：

1. 对照真实来源排除字段/基准误读；把高度、厚度与可见部分分开。
2. 用当前实际可用工具制作必要示意/编辑参考；已有asset transform可裁切、修补、蒙版、合成、标字、缩放，但不是“输入毫米就自动建模”的工具。
3. 纯参数绘图或简模仅在实际已有工具和授权支持时使用；没有就保留明确文字结构方案、已有参考或保守视角，不安装新平台冒充完成。文字方案不能称已画示意。
4. 回读编辑稿实际像素/父链，确认目标轮廓、草稿标识及不复制项；再在计划中冻结参考职责。
5. 有精确母版/实拍/正确简模时，可选择确定性产品层＋AI环境；没有硬约束能力时，参考仍是软引导，不承诺CAD级毫米精度或模型必服从。

## 结构纠偏的控制前检与三层对照

本节整合[#16局部截面复核](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/16#issuecomment-6920452798)与[结构控制增量](https://github.com/NelsonLongxiang/ecom-retouch-flow/issues/16#issuecomment-6922214210)，用于阶段4/5/7。原案例的像素计数、架体数量和板厚不是通用门槛；调研建议不证明当前工具具有对应能力或效果，也不授予新调用权限。

### 实际能力和制作路线

在既有design/plan及真实请求记录中分别核对：从零生成、编辑已有图或已获同意的分层合成；目标图和参考图的实际顺序、media/hash与职责；工具/模型/接口实际支持、本次实际发送和响应能确认的控制。支持不等于发送，发送不等于服从；缺回执就保留未确认。当前公开API profile没有input_fidelity、边缘或深度字段，不能添加未知键或在prompt里写“深度控制”就声称已启用。

按风险先核商品轮廓、截面、数量和连接，再核道具支撑，最后处理环境。优先复用有据的正确母版、清晰端部或目标轮廓参考；不只在错误结构旁标尺寸，不同时要求保旧错误外形和改外形。空架/简化图只在必要、能力可用且预算允许时制作，不强制每轮额外出图；未知隐藏几何仍UNKNOWN。

保留用户已选的整图生成或编辑路线。严格保真可提出正确实拍/有据渲染商品层＋AI环境，但改变已确认路线须取得相应取舍，不能默默切为合成。模型mask是软引导，不保证精确形状或区外不变；保真、边缘/深度控制须有实际兼容管线、控制图、支持证据及适用授权才可选用，不自动安装、部署或切付费服务。推断深度不是公制测量，错误控制图也可能锁定错误。

### 分别观察目标参考、原生返图与最终合成

每层按确切media/hash、坐标和适用视角保留独立观察；缺层、尺寸/视角不可比或没有实际查看时，不猜模型或后处理根因。原始输出、派生、检查和接受分开保存，不改写旧prompt、回执或FAIL。

| 对照证据 | 判定和最小下一步 |
| --- | --- |
| 目标参考含糊或仍锚定旧错误外形 | 回阶段2/4修来源、职责或轮廓表达，不重复堆同一prompt |
| 原生返图仍无可验证的目标结构改善 | 不称模型已修好；回参考/制作方法或实际能力选择，不能无证据把问题全归给后处理 |
| 原生已符合目标，最终合成却丢失新轮廓或留下旧板边/旧影子 | 有逐层对照才能定位本地擦除/掩膜/合成FAIL；授权内修本地派生并复看，不再次收费生成已取得的正确原生结果 |
| 只有木纹/光影等大量像素变化，错误截面未变 | 变化量不证明结构达标；保留可见结构FAIL，缺可比证据时UNKNOWN |
| 编辑域外EXACT_MATCH，目标截面仍不正确 | 仅证明该域外字节保全，不证明形状、模型服从或整图接受 |
| 截面专项修正满足，原长度等FAIL未处理 | 只记专项结果，旧FAIL和整图未达标状态保留；当前用户范围内所有必检满足后才进入交付流程 |

原生未改对和合成损失可以同时存在，分层记录而非二选一。旧错误商品层即使完整保留也不是正确基底；用户确认局部范围不等于接受整图所有旧问题。

### 改轮廓的允许编辑域

在当前授权范围内核对编辑域是否覆盖：旧产品需要擦除并回补墙面/背景的区域、目标新轮廓、必要接触阴影和接缝；使用真实坐标、源/目标hash和蒙版。只将新木纹复制进固定旧木材掩膜会保留错误外形/旧影子；域内变化量和域外精确保全均不是结构成功证明。模型mask和确定性合成域须分别核对，局部编辑仍检查全图构成、边缘和接缝。

所需擦除、回补或阴影超出原批准范围、坐标不匹配或涉及无关房间时，先停受影响步骤并说明最小缺失权限，不直接扩大region/蒙版或覆盖旧授权。获准修复后保存独立派生并复看新hash，保留原生结果；received只恢复，不重发。

同一结构问题经文字/软参考仍不改善时，主动依据上述三层证据改变参考或制作方法，不无限强调文字或整图重生成；只能在实际可用且获准能力中升级控制。unknown先对账，次数/费用用尽或控制不可用时明确停因，专项UNKNOWN不覆盖其他已知FAIL。

## 场景、书籍与可检查定义

### 书籍：相框式靠墙倚放

以下为用户新增的通用摆放场景定义，适用于涉及需要摆放书籍的场景；它是场景制作与复核要求，不是商品规格、真实摆放证明或图像调用授权。替代本节此前允许邻书或独立道具作为倚靠的宽泛表述，不覆盖已派发请求的冻结意图。

所有书籍采用“相框式靠墙倚放”：把每一本合上的书当作一幅摆在置物架上的相框来陈列，封面完整朝向镜头，书脊不朝向镜头。

书本的下边缘水平落在置物架承托面上，位于前挡板后方；书本整体在前后深度方向小幅向后仰，上部背面自然靠住后方墙面，形成真实的两处支撑：下方由架面承托，上方由墙面倚靠。

从正面看，书本基本端正，左右边缘接近竖直，不要把封面在画面里向左或向右旋转。后仰应通过轻微透视、可见的书本侧边以及贴墙接触阴影表现，而不是通过左右歪斜来表现。

参考画面中相框的倚放方式，但书本仍然是书本：保留封面、书脊和纸张边缘，不要变成装框画，不要添加相框支脚、展示支架或置物架侧板。

保持自然、松弛、有生活感的陈列；书本之间留适当间隙，不相互斜压、不平放堆叠。

应用时先回读当前任务和画面条件，把该定义写入关联的原生design/spec及新冻结步骤的prompt/参考职责/适用保持项。场景必须真实具备可倚靠的后方墙面与承托关系；缺墙面、缺架面或原商品无前挡板等条件与定义不相容时，仅暂停或调整该摆书方案，选择与实际商品一致的场景；不凭空加墙体接触、挡板、支架或侧板，不擅自改成邻书支撑。只询问资料确实不能解决的场景取舍，不重复确认已有明确规则。既有在途请求先收妥或对账并保留原prompt/结果，新规则另冻结计划，不改写历史、不换键重发。

实际看图逐项核对：每本书是否合上、封面完整正对镜头/书脊不正对镜头、下边缘水平落架面且在前挡板后、上部背面真实靠墙、仅前后方向微后仰而非左右旋转、透视/侧边/接触阴影是否支持后仰、书籍身份和纸张边缘是否保留、有无新增支脚/支架/侧板、书间间隙及是否斜压或堆叠。明显违背要求记对应项FAIL；接触被遮挡或看不清记UNKNOWN，未看NOT_RUN，不凭prompt或总体美感填PASS。不要追加未获要求的后仰角度数值、书籍数量或毫米精度标准。

检查实际像素中的书籍数量、商品数量、承托点、倚靠点、可见结构与遮挡范围；数量/构成来自当前来源，不从“美观”推断。用户认可摆放定义或视觉效果，只保存其认可范围，不补造成完整尺寸/安全结构/整套图片接受。

## 原生接手与执行映射

先读project brief.documents，再artifact show获取正文。一个关联任务的**普通原生design主文档**可承载以下可读提纲；这是正文约定，不是额外CLI参数或机器已执行的schema：

| 正文章节 | 接手必须能读到 |
| --- | --- |
| 身份／阶段 | 当前project/task/goal、SKU适用域、用途、七阶段位置、缺口、最小下一动作及停止条件 |
| 方法与来源 | 采用的公共方法spec/citation ID/version/content_hash、条件/边界；本SKU来源与精确摘录 |
| 参数与结构 | facts ID/version/hash和所用field keys；单位/对象/轴/基准；部件、数量、接触面、未知/冲突 |
| 成像与参考 | 相机/遮挡假设及反例；每张参考ID/hash/父链、角色、真实/示意字段、禁止复制项及优先顺序 |
| 控制／计划 | 实际prompt与实验控制的区别；输入/蒙版坐标、真实支持选项；plan ID/hash、适用执行/外发/费用次数权限 |
| 观察／消费者 | exact media/hash的分项判断、用户反馈/接受范围、当前计划和引用哪些版本；变更后须复核谁 |

- 公共方法发布正文先用已有spec register或design register（agent-interpretation/reference等真实角色）保存；应用到SKU时用context search/cite取得源工作区/project/artifact/version/content_hash/purpose/conditions，阅读后写入本任务design。通用方法与SKU实例分开，不把此公共说明改成真实业务事实。
- 不使用method register的标签分类schema承载几何；context cite当前只接受design/spec，不能声称已能引用任意media对象。图片先按实际asset add或asset transform登记到当前项目，再在design记录其真实角色/父链。
- 通过[既有CLI](CLI.md#原生文档与导出)登记/修订普通design/spec；当前主design绑定任务后，修改用artifact revise携带已读ID/version/content_hash，不用新文件名假装版本。额外并列design会改变任务design指针，须明确其用途；不要反复注册同义主文档。
- facts register沿用retouch.product-facts/v1，每个字段绑定实际来源；来源的完整身份/基准也写在设计及来源正文。只在真实依据变化时修订facts，不能因prompt或示意修改而改实物值。
- plan submit冻结所用facts和当前design ID；每步真正依赖的fact_keys、safe_strategy、invariant/coverage等沿用现有契约。设计正文不会自动成为模型prompt，也不自动跟踪其中任意自由文本ID：Agent必须阅读并把必要条件和禁止项编入当前步骤。

计划references的**现有字段示例**（ID须来自实际响应）：

~~~json
{
  "id": "blend-reference",
  "prompt": "仅按本SKU来源保持实体结构；按非成品编辑稿修正可见轮廓，修复接缝/台阶/阴影；不复制标线，不恢复旧错误轮廓。",
  "needs": [],
  "fact_keys": ["dimensions.back_height", "dimensions.front_height", "dimensions.board_thickness"],
  "references": [
    {"media_id": "<实际材质参考media>", "purpose": "仅参考材质；旧错误轮廓不得作为结构锚点；不是其他SKU规格来源"},
    {"media_id": "<实际编辑稿media>", "purpose": "非成品、非实测；只指导目标轮廓；去掉标线，修复台阶/接缝/阴影，不恢复旧错误轮廓"}
  ]
}
~~~

现有plan会核参考media归属和非空purpose；host job携带职责及实际media/hash，API提示词按实际参考顺序列用途并声明不作为规格确认。**这些校验不自动识别角色冲突、未标编辑稿或模型是否服从**，须由Agent在阶段4/5预检和阶段7实看。API fallback仅在明确选择及授权齐备时用；实际模型不支持的参数不能写成已生效。

## 在途变更、版本与ZIP恢复

请求已派发时，新书籍规则/轮廓要求不能倒填旧prompt。先收妥或对账旧请求，保留真实输入、控制、结果与不符合项；unknown不换键重发，received只走本地恢复。旧图适用性另审，不强制作废可用结果。需要新执行时，再读当前需求/事实/设计，复核旧候选或另冻结新计划和适用授权；不把“新需求”当旧请求重试许可。

公共方法或SKU设计更新时保留旧版本与精确引用。context build诊断stale/unavailable/conflict，artifact revise按已有绑定使相关任务/消费者待复核；**自由正文里未登记的消费者不会自动被软件发现**，Agent须在设计中列出并回读受影响任务，不声称全项目自动传播。新要求不清除旧unknown，也不沿用旧接受。

context export→inspect→import --dry-run→import保全原生来源、设计、引用、参考角色/父链与真实CAS；图片预览ZIP不是完整工作区。引用的文字快照不等于引用源媒体已一并复制：需要的原生media和CAS必须真实进入当前项目并核包内保全。恢复不出图，源执行授权隔离；新工作区继续执行须有适用新授权。此方法没有新增required capability，不能据此假称旧客户端会自动执行新几何语义；仍由读取正文的Agent遵循。

## 返图反例与返回阶段

| 观察／证据 | 判定与返回 |
| --- | --- |
| 当前基准、构型、视角及遮挡条件已确认，实际露出关系仍与冻结设计矛盾 | 对该可见关系记FAIL，回阶段3/4；不把45改30迁就模型。只有45/25来源可靠、缺成像条件时不能据此判FAIL，应记UNKNOWN并回阶段1/3 |
| 同SKU展开/折叠、档位或载荷不同，尺寸看似不一致 | 先区分合法测量状态与对象，不自动记冲突；来源约数/范围/精度原样保留，主张所需条件不足为UNKNOWN |
| 高度有原文，厚度/基准看不清或未知 | 高度来源可保留；精确厚度/完整几何UNKNOWN，补影响画面的证据或选择保守视角 |
| 原图保旧轮廓与编辑稿改新轮廓同时要求保持 | 阶段4职责冲突，先裁定用途，不派发矛盾参考包 |
| 草稿未标非成品／标线或接缝台阶保留 | 回阶段4明确标识/修稿；最终像素有明显残留则FAIL，不靠总体风格PASS |
| 书籍左右歪斜/书脊朝镜头、未落架面或未靠墙、相互斜压/堆叠、变成装框画或新增支脚/支架/侧板 | 对已可见的对应摆放/构成要求记FAIL，回阶段2/4/5；接触不可辨为UNKNOWN，未看NOT_RUN，不靠遮满商品或虚构接触过关 |
| 轮廓和摆放获用户认可，但无法量出毫米厚度 | 保存视觉/定义的真实认可范围，毫米精度仍UNKNOWN；不补整套接受 |
| 根本未查看最终文件或工具无图像能力 | 实际视觉NOT_RUN，不提交虚构PASS；已声明覆盖未评估可由既有视图表示NOT_EVALUATED |

记录使用现有visual/invariant/coverage review的合法verdict，NOT_RUN是“尚未执行观察”的验证状态，不向只接受PASS/FAIL/UNKNOWN的接口伪造新枚举。明确相反的必检项FAIL、证据不足UNKNOWN、未看NOT_RUN，均不能被文件齐全、doctor、fixture或总体美感越过。只对确切hash复核；新的派生需重新检查，用户接受和文件交付另行处理。

## 开发验证与能力边界

首版复用已有schema和公共接口，新增方法/Skill入口及针对性用例；不是重开#9或新增自动物理渲染平台。静态文档与合成字节测试只验证描述、来源/事实/提示词传输和边界，不能证明实际生图、物理准确、独立视觉盲审或跨商品收益。

验收应分层留证：文档/链接/元数据；现有facts/提示词的确定性回归；真实原生brief/plan/引用/修订/ZIP接手；当前工具的实际模型观察；独立保留结构/视角反例；真实用户认可；跨SKU相对收益。未执行分别记NOT_RUN，缺证据不评分；已披露合成案例不是未见盲测。至少由非编写者在候选固定后选取未用于提炼的结构/视角反例，检验适用性，不回填成已知答案后仍称盲测。

本Issue的实现/验收与#12在途补丁分开；不重写旧失败和受审身份。真实调用/费用、合并、发版和业务接受继续按各自授权，方法论形成不产生额外调用权限。
