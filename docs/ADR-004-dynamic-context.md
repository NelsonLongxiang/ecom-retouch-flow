# ADR-004：动态上下文工程

状态：ACCEPTED（2026-11-15 用户确认开始）。产品定义为动态上下文工程，范围为所有登记工作区，底层为 ygl-trees CLI 的高级封装。0.2.0 独立账本属于待迁移历史基线，其技术测试不作为新架构验收。

## 上下文

项目管理和 ZIP 交换已经提供稳定事实、版本、引用基础与接手入口。用户进一步要求项目标签可更新、跨项目复用 design/spec、评分与结语提醒、按标签统计全局品味，并通过二次分类得到更专业的建议，将这一行为定义为动态上下文工程。

仅查看高频词不足以解释它表达的是风格、材料、修图部位还是满意度。跨工作区恢复还会产生同一项目的多个实例；直接按目录计数或选择最新时间，会放大频率或掩盖冲突。

## 拟议决策

以 ygl 原生 project/task/produce/rel/research/kb、节点与索引作为承载，retouch 只做电商领域 schema、CLI 编排、素材处理、ZIP 交换和上下文视图。禁止另建业务账本、全局搜索库或用 db sql 绕行创建一套影子系统；能力不足优先通过 ygl 原生 CLI／插件扩展补齐。此裁决替代 ADR-003 中“独立账本为权威、ygl 为投影”的决定。

标签、评分、结语、完结与引用保留版本及来源，方法论声明如何二次分类和统计，Agent 根据原生检索命中的 design/spec 形成建议，用户反馈继续回到 ygl。

所有登记工作区参与检索，但同一稳定项目身份只计一次；实例分歧依据有证据的版本链或用户指定权威处理。无法确定时保留冲突，不按时间戳猜测。引用使用稳定来源身份、精确版本/hash 和可携带副本，不把源商品事实直接升级为目标商品事实。

先收敛原生封装并迁移复验现有能力，再完成标签反馈、跨工作区检索引用和版本化分类／建议闭环。原生接口证据及缺口见 [迁移规范](YGL-WRAPPER-MIGRATION.md)，业务方法论见 [路线规范](DYNAMIC-CONTEXT.md)。

## 后果与取舍

需要迁移现有独立账本、补原生幂等／导入缺口和验证 ZIP 兼容。工作区移位、失联、身份重复、分类漂移及反馈缺失必须可见；跨工作区统计是对原生数据的视图，不能演变成另一套业务引擎。

提醒进入现有业务入口，不引入默认后台任务；未评分不阻止执行。频率、共现和满意度分开呈现，建议不能被报为用户事实或图像质量结论。现有图像授权、unknown 对账、跨项目绑定与不重复出图约束保持适用。
