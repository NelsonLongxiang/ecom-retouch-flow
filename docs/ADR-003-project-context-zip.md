# ADR-003：业务领域关联与可移植 ZIP 上下文

## 上下文

Issue #1 记录外部候选、正式运行状态、方案文档与用户目标分离；Issue #2 要求通过单个 ZIP 在其他会话和工作区恢复完整项目。复制 SQLite 会同时复制机器绑定、租约和投影状态，只压缩摘要无法恢复真实对象、版本及请求历史。

## 决策

扩展现有领域账本，增加 Project、版本化 Goal、Design、Artifact、Execution、Review、Provenance 和有统一语义的 Relation。任务显式绑定项目、目标版本及终止条件；旧工作区显式迁移，不推造历史项目或授权。已有 Service 继续管理正式图像运行，外部事实通过同一账本接入，状态查询共享这些事实。

项目摘要和 SQLite 查询索引从领域记录实时生成。ygl 保存可重建的计划／运行证据和带源指纹的项目投影；域记录先提交，投影失败明确 pending。修投影不执行图像操作。

交换格式固定 ZIP：manifest + Markdown 摘要 + 结构化记录 + 去重 CAS 对象。同步获取账本快照，异步读取不可变对象，校验临时包后独占发布。导入先在内存校验包、全部对象、实际图片尺寸和关系，再安装 CAS、事务提交记录，最后重建本机投影。首次导入中断使用 import_pending 阻止业务误用，重导同包恢复；非空工作区冲突不覆盖。明确 clone 才重映射逻辑身份，保留来源映射。

历史确认和来源事实保留，执行权限按目标工作区另行核对；导入不恢复进程租约、源目录交付权限或原认证。unknown 保持 unknown，重复快照不创建业务对象或触发工具请求。

## 后果

新任务必须提供项目／目标绑定；文档设计可独立建任务，完成方案文档不等于图片完成。CLI、技能、演示和夹具随接口同步更新。

完整项目 ZIP 有明确大小上限，不提供局部导出或按时间戳合并。缺失材料、不可移植文档或冲突需要先修复；pending 的 ygl 可在领域数据保留后补建。格式校验不构成包签名或同 OS 恶意 Agent 沙箱。验收同时覆盖原有工作流、历史事实回放、ZIP 攻击面、故障恢复和真实 ygl CLI。
