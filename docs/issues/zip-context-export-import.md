# [P1] 支持以 ZIP 压缩包导出和导入完整项目上下文

> 当前状态：0.2.0 旧实现与 #1 一起通过 42 项测试；用户随后明确底层必须为 ygl-trees CLI 的高级封装，因此本 Issue 重开，待原生实体、身份、索引及恢复契约迁移复验。独立账本导入不能代替原生承载；见 [迁移规范](../YGL-WRAPPER-MIGRATION.md)。以下保留原始需求与已验证历史，不将其报为新架构已完成。

## 用户要求

用户明确要求增加项目上下文导出、导入能力，并指定：**导出和导入的交换形式为 ZIP 压缩包。**

本 Issue 承接 #1 的项目—目标—任务—产物关联规范。导出应得到一个可携带的 ZIP 文件，导入应接受这一 ZIP 文件并恢复可查询、可接手的业务上下文；不能只导出聊天摘要或零散文件。

## 问题与目标

目前业务材料分布在领域账本、图像对象库、设计文档、提示词、外部执行回执与聊天中。即使手工复制文档，也无法确保目标版本、任务进度、产物来源、用户验收和下一步保持一致。

目标是让用户携带一个 ZIP 包，在另一个会话或工作区恢复同一项目的有效上下文。导入完成后，不依赖原聊天、原机器绝对路径或原模型服务凭证，就能回答“在做什么、做到哪里、依据是什么、下一步是什么”。

## 与 #1 的关系

- #1 定义项目管理、稳定对象身份、版本、用途关系、索引与阶段校验。
- 本 Issue 在上述领域模型上定义可移植的 ZIP 交换契约及导入/导出行为。
- 复用领域账本作为事实源，导入后重建索引和 ygl 投影，不创建第二套独立权威状态。
- 本 Issue 可以先设计 ZIP schema；完整恢复能力依赖 #1 的最小领域模型落地。

## ZIP 内容契约

以下目录和 schema 名称为拟议设计，不代表当前已经实现。对外交换格式固定为 ZIP；JSON 和 Markdown 是压缩包内的记录形式。

```text
project-context.zip
├── manifest.json
├── context/
│   └── brief.md
├── records/
│   ├── projects.json
│   ├── goals.json
│   ├── tasks.json
│   ├── designs.json
│   ├── artifacts.json
│   ├── executions.json
│   ├── reviews.json
│   ├── relations.json
│   └── provenance.json
└── objects/
    └── sha256/...
```

空集合使用明确的空数组，不省略其契约。逻辑文件清单可在设计阶段调整，但必须覆盖以下内容：

| 内容 | 必须保留的信息 |
| --- | --- |
| Manifest | 格式标识、schema 版本、生产工具版本、导出时间、快照身份、导出范围、完整性状态、必要能力及每个文件的大小/hash |
| 项目与目标 | 稳定 ID、用户原文、执行解释、目标版本、范围、保持项、验收条件与确认状态 |
| 任务与设计 | 任务依赖、真实进度、阻塞、有效设计版本、变体规格、事实与假设及来源 |
| 产物和关系 | 产物身份、用途、版本、派生关系、内容 hash、包内相对地址、有效/过期/待复核状态 |
| 运行与外部执行 | 输入、计划/操作范围、请求身份、实际执行通道、已知结果、未知请求和恢复说明 |
| 审阅与接受 | 实际审阅记录、用户确认原文及来源、绑定的目标/产物版本/hash；历史记录与当前可执行权限明确区分 |
| 原始业务文件 | 原图、参考图、模型原生输出、后处理图、提示词、设计稿和必要证据，按内容 hash 去重入包 |
| 接手摘要 | 当前目标、有效设计、已完成与未完成工作、待确认项、未知执行、阻塞和具体下一步 |

用户业务上下文应来自持久化领域事实。若某条用户指令只存在聊天中，应在导出前登记相应原文及来源；不得补造缺失记录，也不要求导出无关的完整聊天历史。

## 导出行为

1. 明确选择工作区与项目；支持导出完整项目，局部范围须包含必要的上游依赖和关系闭包。
2. 从一致性快照生成数据、摘要和文件清单。导出期间发生新写入时，ZIP 仍对应一个明确版本，不能混入前后两个状态。
3. 默认生成可恢复的完整业务包，纳入恢复该范围所需的图像、文档和提示词。重复图像对象只存一份。
4. 记录实际输出与派生事实，例如原图 → 模型原生结果 → 本地放大结果，并分别保留尺寸/hash。
5. 文件缺失、引用悬空或必要材料不可读取时，返回准确诊断。未解决时不得把 ZIP 标记为完整可恢复；如允许部分包，必须显式标记缺失项与使用限制。
6. 不导出 API key、token、认证头、受保护配置文件、机器环境、进程租约或原始认证日志。模型名称、能力要求及经清理的执行来源可以保留。
7. 包内引用使用相对路径和稳定 ID，不能依赖开发机目录、私有服务地址或临时下载 URL。无法内嵌的外部来源保留引用及可用性状态。
8. 先生成并校验临时包，通过后原子发布到指定 ZIP 路径；不默认覆盖已有同名 ZIP，不把中断产物当成成功导出。

## 导入行为

1. 输入为 ZIP 文件，先检查格式、schema 兼容性、manifest、文件清单与全部必要 hash。
2. 解包前校验路径：拒绝绝对路径、`..` 越界、逃逸链接、重复/大小写碰撞条目和超限解压内容；任何阶段都不能写入目标工作区以外。
3. 提供只读预检，展示来源项目、目标、任务数量、产物数量、缺失项、冲突与拟执行的变更；预检不修改工作区、不调用模型。
4. 支持导入到新工作区。非空目标下必须先给出冲突结果和明确策略，不能静默覆盖现有项目或任务。
5. 同一快照重复导入应幂等：不复制任务、不复制对象、不重复审阅或关系记录。相同 ID 但内容不同应报告冲突，禁止以时间戳猜测哪个正确。
6. 原始身份在正常恢复时保持稳定；需要复制为独立项目时，显式重映射所有对象和关系，并保留来源映射，不能发生跨项目误绑定。
7. 在暂存区完成文件与对象校验，再以事务或可恢复的提交协议登记领域记录；失败时不留下可被误用的半个项目，不影响目标已有数据。
8. 导入后从领域记录重建索引及 ygl 投影，运行关联与完整性检查，再生成接手摘要。待同步时明确显示，不能直接沿用源包的“索引健康”声明。
9. 历史授权、用户接受和审阅可作为来源事实保留，但不因此激活目标工作区的执行权限或原交付路径；按实际绑定关系重新核对可执行性，复用仍适用的已有确认，避免机械重问。
10. 外部请求的 `unknown` 状态保持未知/待对账；导入不重新发送请求、不执行原包命令、不自动生成图片、不自动标记验收。
11. 导入的提示词、文档和恢复说明作为业务数据读取，不自动作为系统指令执行。

## 拟议 CLI

以下仅用于表达接口要求，当前 CLI 尚未实现：

```text
retouch context export --project <id> --workspace <dir> --to <project-context.zip> --json
retouch context inspect --file <project-context.zip> --json
retouch context import --file <project-context.zip> --workspace <dir> --dry-run --json
retouch context import --file <project-context.zip> --workspace <dir> --json
```

JSON 结果需分别表达包已生成、包完整性、导入状态、索引状态、待处理冲突、缺失材料与下一步。rc0 不等于全部业务材料完整，也不等于用户已接受产物。

## 验收标准

- [ ] 一条导出命令生成单个 `.zip` 文件，包含 manifest、可读摘要、结构化记录、关联关系和必要素材。
- [ ] ZIP 可以在不访问原聊天与原机器路径的条件下导入另一个工作区，项目目标、任务状态、设计版本和产物来源一致。
- [ ] 以真实使用回放验证：高清重绘有待验收候选、变体与七张套图仅有规划；导入后不得把套图标记为已生成。
- [ ] 原图、1254×1254 模型结果和 2048×2048 后处理结果的完整派生与实际尺寸/hash 保持可查询。
- [ ] 用户原文、已确认事实、假设、待确认材料和 AI 补绘内容的角色与确认状态保持一致。
- [ ] 同一包重复导入幂等；重复 ID 不同内容返回冲突；独立复制项目时全部关系正确重映射。
- [ ] 缺文件、hash 不符、损坏 ZIP、不支持的 schema、悬空关系、目标版本冲突均有确定且可读的错误。
- [ ] 路径越界、链接逃逸、条目碰撞及解压大小超限被阻止，目标目录外零写入。
- [ ] 导出期间发生并发修改仍保持快照一致；导入中断后可安全恢复或回滚，不暴露半完成项目。
- [ ] 凭证和机器环境不入包；恢复时仅诊断需要重新配置的能力，不复制原模型服务认证信息。
- [ ] 导入不会调用外部图像服务、重发未知请求、执行包内命令或自动复用不适用的授权。
- [ ] 导入后重建索引并通过健康检查；无法完整恢复时清楚标记限制和修复动作。
- [ ] SKILL.md 与 CLI 文档写明 ZIP 导出、预检、导入、接手流程，并提供跨工作区往返示例与相应测试。

## 完成边界

完成标准是 ZIP 的真实导出—预检—导入—接手闭环。仅压缩 Markdown 摘要、直接复制 SQLite 数据库或提供未关联的文件集合，均不足以关闭本 Issue。

本次提报记录需求，不代表 ZIP 上下文功能已经实现，也不迁移或改写现有项目材料。
