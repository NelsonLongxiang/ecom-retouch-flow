# ADR-005 · Validation convergence without a second validator repository

## 上下文

The existing EcomRetouchFlow repository owns its retouch CLI, native ygl adapter, deterministic image processing, tests and validation runner. The baseline is commit 5cef8cb9227aaf3414c638fb52c614f74ed0b944 (unmerged PR20). Issue18 remains a separate unmerged Draft PR19 with INCOMPLETE independent acceptance; it must not be silently included here.

A bounded inventory found existing developer helpers and native knowledge records, not a missing platform. A real regression was reproduced: invoking the CLI through a directory discovery link returned exit0 with empty stdout, while the canonical path returned one valid CLI JSON object. Existing native developer transport also retained only truncated diagnostics and inherited an unconstrained child temporary directory.

Software PASS, an intended business-rule FAIL, verifier self-check, business visual FAIL and production acceptance are separate observations. The reported real bottom-panel result remains FAIL; this source convergence neither reads its image bytes nor changes its native review. Source metadata and historical evidence contain absolute origin paths for provenance, not executable dependencies.

## 决策

1. **One home.** Maintain capabilities in this repository: product implementation in src/, maintained validation transport/producer in existing scripts/, native/runner regressions in tests/, architecture and readable results in docs/. Do not create another verifier repository, ledger or engine fork.
2. **Project pack.** If the installed ygl0.125.0 contract is supported, keep the project validation material, candidate predicates, reviews and known-good/bad fixture descriptions under verify/packs/retouch-validation/. This is data only; no executable code is moved into the pack. Global validator rules stay upstream. This candidate uses the explicit project-local manifest schema, not a falsely frozen upstream pack. Upstream prepare/run and corpus self-check in ygl0.125.0 automatically unlink temporary snapshots or corpus directories, so they are NOT_RUN under the no-delete instruction. Project-native positive/negative/self-check evidence is separate. Do not register the draft as an executable instance before its upstream freeze/run contract is genuinely satisfied; no automatic schedule is introduced.
3. **Execution.** Reuse scripts/test.mjs, scripts/lib/native-ygl.mjs and NativeClient. Resolve CLI entry identities through realpath so canonical and linked execution work while importing the CLI stays inert. Native developer calls require explicit home/cwd/session and retain actual exit/signal/timeout/parse state and complete captured stdout/stderr under a project task tmp root; no hidden success on empty JSON. Only child TMP/TEMP/TMPDIR change; host/global configuration does not. Developer native fixtures opt into retainRequests when initializing and reopening isolated workspaces; default business cleanup behavior is unchanged. Actual implicit engine lock lifecycle is not claimed as whole-call-chain zero deletion; source assets and retained requests are the declared preservation boundary.
4. **Scope and immutable evidence.** The two-pass inventory includes declared src/scripts/tests/docs validation surfaces, direct dependencies and selected task metadata. It excludes unrelated roots, business images/CAS, dependency recursion, archive contents, live locks/caches and deployment mirrors not supplied. Machine asset maps include absolute source/root, full Git SHA plus display SHA16 or no-SHA, content hash, owner, activity, consumer, disposition and preservation. Exclusions and unresolved consumers remain PARTIAL, never ALL_CLEAN.
5. **Preservation.** Copy selected originals exclusively into the existing ignored docs/verification/runs evidence area; retain source bytes. No deletion, move, forced reset, worktree, clone or stash. New SUPERSEDED pointers identify successor navigation/evidence where appropriate, never replace old reports or their verdicts. Runs and machine/business metadata do not enter Git. A source change is traced by Git plus its preserved predecessor, not by overwriting a delivered artifact.
6. **Evidence gates.** An isolated positive must actually PASS. The negative must execute the intended required-item rule and return FAIL with witnesses, not crash, skip or miss material. Self-check must report PASS. Keep business visual FAIL outside the software success aggregate. Test reports freeze source identities, verify native receipts and separate process rc from domain verdict. Same-SHA independent review follows the narrow candidate commit; later changes require rechecking the changed identity.
7. **Native work record.** Reuse the existing explicit design knowledge workspace and project after KB/task deduplication. Native task/arch decision/spec/kb/relations record real actions and evidence references; doctor checks workspace health, not business correctness. No arbitrary SQL writes or new business tables; fixture databases are isolated test inputs only.

## 后果

- **P1:** fix the reproduced linked-entry failure and developer transport completeness/project-temp gap; add exact entry, permission/invariant and output-integrity regressions.
- **P2:** freeze a source-relative project pack and bounded source/metadata asset maps; exercise positive, intended negative and self-check using installed native primitives without model/network requests.
- **P3:** retain old originals and successor pointers, rescan imports/entry points and hand the exact committed SHA to the existing independent reviewer. Commit/PR delivery is not merge or deployment permission.
- **Deferred / not covered:** hidden geometry, real bottom-panel improvement, model obedience, business image acceptance, all legacy tmp consumer activity, unspecified deployment mirrors, same-OS hostile writers and global host spill policy. These remain explicit limitations; the convergence report cannot erase them.
- **Recovery:** the base Git commit, exclusive predecessor copies and copy manifest identify original bytes. To undo a future authorized change, first inspect concurrent work and apply an explicit reviewed inverse revision. Do not delete new evidence or overwrite later work as a rollback shortcut.
